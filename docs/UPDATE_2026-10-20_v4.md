## Interpretation of "increase the pattern tool by 100%"

Taken as the **painting footprint**: pattern radius 56 → 112 page pixels (others stay 56). The toolbar control is a Figma-defined circle shared by all tools and was not changed; the earlier doubled *preview* is removed by request 14. `PaintDocument.MaxRadius` was raised from 100 to 224. If a larger toolbar icon was meant instead, change the Pattern diameter in `KidoApp` layout.

## Page geometry (request 12)

Old: a 1536² page with the artwork in the middle; the display was mapped piecewise so the 256 px gutters were stretched to whatever screen space remained, differently on each side. Brushes became ellipses and patterns skewed in the gutters.
New: one uniform scale (artwork-size / 1024) for the whole page, applied identically by touch (`DrawingSurface.ToPage`) and by the shader (`_PageMap`/`_ArtMap`). The page is now **2048 × 1536** (512 px side and 256 px top/bottom margins) so it covers a 16:9 phone's white area; very wide screens (> ~19:9 after safe area) clamp the page edge outward instead of stretching.

Saves: new saves are `<id>_page2`. Older `<id>_page` (1536²) and original `<id>` saves are read, reframed in memory (artwork stays aligned) and the old files are left untouched. Same file format, checksums and two slots.

## Other behaviour changes
- Autosave no longer renders/encodes a thumbnail each time; it does so once when idle after a save, on Done/Escape, and at startup repair.
- Audio SFX for Done is a synthesized rising arpeggio.

## Bugs found by running it natively (not in the request list)
- **Confetti/star bursts never rendered**: `KidsEffects` (a custom `Graphic`) had no `CanvasRenderer`, so the Done shower and the release star bursts drew nothing. Fixed with `[RequireComponent]` (also on `ToolGlyph`).
- **Done threw in the Editor**: `GetComponent<CanvasGroup>() ?? AddComponent` — `??` bypasses Unity's null check. Now `TryGetComponent`.
- **Torn / mismatched saves threw** instead of falling back to the other slot: `InvalidDataException` was not in `PaintStore`'s catch filters (two existing PaintTests failed on this).

## Verification (what was actually run)
Run with Unity 6000.3.14f1 in **batch mode on a scratch copy** of the project (Library included, company/product renamed so the real save folder was never touched). The open Editor and its `Packages/`/`ProjectSettings/` were not modified; the Pipeline package is not installed so there was no live Editor connection.
- EditMode: **30 / 30 passed** (16 existing + new: tap-seek does not select intermediates, uniform page mapping, pattern = 2x brush, legacy `_page` reframing; two existing tests corrected).
- PlayMode harness (copy only, not shipped): boots `KidoApp`, waits for the menu, opens an artwork, paints, taps Done, waits for the menu, checks the thumbnail file, reopens (3,145,728 painted pixels before and after). Screenshots at 1600x900, 1422x1067 and 2000x900 are in `docs/ArtQA/v4/`.
- Touch/shape check through real pointer events: brush taps in the far gutters are 112x112 page px; pattern taps 224x224.
- Shader and C# compile clean (Unity compiler, no errors).

Not done: iOS/Android build, real touch devices, audio listening (no audio device; clips imported and referenced only), profiling, the intro/logo motion by eye, Figma comparison (sign-in required), the `node` content checks (need the `sharp` npm package, not installed).
